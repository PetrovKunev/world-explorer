## 1. Къде сме сега

**Стек:** Next 16 (App Router, Turbopack) + React 19 + TypeScript + Tailwind 4,
Leaflet / React Leaflet, Supabase (Auth + PostgreSQL с RLS + Storage).

**Структура:** единствен маршрут `/` → server component зарежда дестинациите →
`AppShell` (header, sidebar, карта, toast-ове).

**Модел `destinations`:**
`name, latitude, longitude, type, visited, visits[] (JSONB), notes, rating,
photos[] (JSONB), tags[] (JSONB), created_at, updated_at`.

**Вече реализирано:** геокодиране (Nominatim), влачене на маркери, клъстериране,
GPS следене и маркиране на текущо местоположение, разстояние до дестинация,
качване на снимки, тъмна тема, PWA манифест, оптимистични обновявания,
търсене и филтри в списъка.

## 2. Блокер, който трябва да се реши преди статистиките

**В модела няма държава.** Най-силните показатели („18 държави, 4 континента,
9% от света“) са невъзможни с текущите данни. Reverse geocode заявката към
Nominatim вече се прави в `MapComponent.tsx`, но връщаният
`address.country_code` не се записва никъде.

**Какво е нужно:**

- Нови колони: `country`, `country_code` (ISO-3166-1 alpha-2), `city`, `continent`.
- Автоматично попълване при създаване на дестинация и при местене на маркер.
- Еднократен backfill скрипт за съществуващите записи.
- Континентът се извежда от `country_code` чрез статична таблица (~250 реда,
  без външно API и без допълнителни заявки).

**По избор, но полезно за статистиките:**

- `home_base` (координати в профила) — за показателя „най-отдалечена точка от вкъщи“.
- `cost` + `currency` — бюджетни статистики.
- `companions` — с кого е направено пътуването.

## 3. Статистики — пълен списък с идеи

### 3.1 Обзор (KPI плочки)

- Общо дестинации
- Посетени / Планирани
- Брой държави
- Брой континенти
- % от света (спрямо 193 държави членки на ООН)
- Общо посещения (сума на дължините на `visits`)
- Общо дни на път (сбор на всички периоди)
- Средна оценка
- Брой снимки
- Брой уникални тагове

### 3.2 Време

- Посещения по година (стълбовидна диаграма)
- Посещения по месец — кой месец се пътува най-много
- Календарна „топлинна“ решетка (месеци × години)
- Най-активна година
- Най-дълго пътуване (в дни)
- Среден престой
- Серия: последователни месеци / години с поне едно пътуване
- Предстоящо пътуване — следващото планирано, с обратно броене

### 3.3 География

- Топ държави по брой места (хоризонтални стълбове с флагчета)
- Континенти като progress bar-ове (напр. Европа 12/44 държави)
- Крайни точки: най-северна / най-южна / най-източна / най-западна дестинация
- „Радиус на изследване“ — най-отдалечената точка от базата, в км
- Географски център на пътуванията (центроид)
- Хронологично изминато разстояние — сбор на отсечките по датите на посещенията

### 3.4 Вкус и качество

- Разпределение по тип дестинация (донът диаграма)
- Разпределение на оценките (1–5)
- Топ тагове
- Средна оценка по тип („най-високо оценявате музеи“)
- Топ 5 любими места
- Най-често посещавано място (по дължина на `visits`)

### 3.5 Постижения / геймификация (по избор)

Значки от типа:

- „10 държави“
- „Първо междуконтинентално пътуване“
- „Всички типове места“
- „Пътуване над 14 дни“
- „Всеки сезон от годината“

## 4. Табло за управление

**Маршрут `/dashboard`** като server component (данните вече се четат сървърно),
плюс превключвател в хедъра: **Карта · Табло · Списък**. На мобилни устройства —
долна навигация с три икони.

**Оформление:**

1. Ред с KPI плочки (4–6 бр., с малки sparkline-и).
2. Филтър-лента: година / всички години, посетени–планирани, тип, таг —
   влияе върху всичко отдолу.
3. Мрежа с карти-графики: посещения по година, разпределение по тип,
   топ държави, календарна топлинна карта, разпределение на оценките.
4. Секция „Рекорди“ + значки.
5. **„Годината в равносметка“** — отделен споделяем изглед (`/dashboard/2026`),
   експортируем като PNG за социални мрежи.

**Технически решения:**

- Без нова библиотека за графики. Нужните типове (стълбове, донът, календарна
  решетка, sparkline) са ~150 реда собствени SVG компонента и пазят bundle-а
  малък; Recharts би добавил значителна тежест заради 5 диаграми.
- Изчисленията — в чист модул `lib/stats.ts` върху вече заредения масив
  (бързо е до няколко хиляди записа). При нужда по-късно → Postgres view + RPC.

**Бонус върху самата карта:**

- Слой „топлинна карта“ на посетените места.
- Линии на маршрута между посещенията в хронологичен ред.

## 5. Други подобрения, които забелязах

| Тема | Проблем | Предложение |
|---|---|---|
| Nominatim | Заявките са директно от браузъра, без идентифициращ `User-Agent` (браузърът не позволява да се задава) — нарушение на usage policy и риск от блокиране | Собствен `/api/geocode` route с правилен header и кеширане |
| `MapComponent.tsx` | 878 реда, 5 компонента в един файл | Разделяне на папка `components/map/` |
| Тестове и CI | Няма никакви | Vitest за `lib/stats.ts` (чисти функции — идеален старт) + GitHub Actions с lint и build |
| Снимки | Публичен bucket — всеки, който има URL-а, вижда снимката | Частен bucket + signed URLs |
| Зареждане на данни | `select('*')` без лимит | Пагинация или лимит при по-голям обем |
| Експорт на данни | Няма | Експорт/импорт в JSON, CSV, GeoJSON, GPX — и застраховка срещу заключване на данните |
| Документация | Пет отделни `*_FIX.md` файла в корена на репото | Обединяване в `docs/` |
| Миграции | Ръчни SQL файлове с припокриващо се съдържание | Номерирани `database/migrations/NNN_*.sql` |
